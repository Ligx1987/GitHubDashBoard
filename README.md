# GitHub Pulse

查看公开仓库的真实计数和代码活动：近 7 / 30 天飙升 Top30（不限创建时间）、近 3 天新建工程增星 Top10、每周新建工程增星 Top10、每月新建工程增星 Top30，以及近三个创建年份各年总星 Top30。只收录近三年创建的工程（滚动窗口，超龄自动移除）。零运行依赖，Node.js 20 或更新版本。

## 需求与设计文档

文档入口见 [文档索引](docs/README.md)。[需求说明](docs/requirements.md) 汇总产品范围、功能、统计口径与验收标准；[技术设计](docs/design.md) 说明架构、数据模型、采集流程及部署约束。当前实现与后续规划分开维护，历史审计记录用于追溯。

## 运行

Windows 可直接双击项目目录中的 `start-dashboard.cmd`，自动在后台启动服务并打开浏览器；重复点击会复用已运行的服务。关闭浏览器不会关闭服务，重启电脑后再次双击即可。启动日志保存在 `.scratch/dashboard.log` 与 `.scratch/dashboard-error.log`。

也可在终端运行（需要保持该终端中的服务运行）：

```bash
npm run dev
```

打开 http://localhost:4173 。首屏读取保存的快照，随后自动请求 GitHub 公开 API，不必填 Token。浏览器每 30 分钟刷新一次；手动刷新、搜索、领域筛选、主题切换均可用。

飙升榜与新建工程榜默认预览前 5 名，可展开完整 Top10 / Top30；工程目录每页 15 项，使用整页滚动。目录优先按主榜共同截止日的周新增排序，旧缓存和未知增长随后按总 Stars 排序，旧缓存显示实际截止时间。手机端采样概览默认收起，点击可查看完整指标与历史覆盖率。工程名称链接到 GitHub，行内“详情”可展开完整描述、原文、次分类、Forks 和采样信息。一周趋势图与辅助净增切换已移除；侧栏高亮随阅读位置更新。

本地服务保持运行时每两小时自动执行一次持久化采集；启动时如果上次采集距今超过两小时，也会启动一轮。关闭服务后本地采集暂停，不会安装系统定时任务。设置 `GITHUB_PULSE_AUTOSYNC=0` 可关闭本地后台采集；不要同时手工启动另一个采集器写同一组文件。

浏览器每批查询近 3 / 7 / 30 天新建候选和一个创建年份，每组取按总 Stars 排序的前 100 个结果，四个年度在成功批次间轮换。近期查询多覆盖一天以容纳接口日界差异，入榜时仍严格按实际统计窗口筛选；不设最低 Stars 入榜门槛。结果合并进已收录集合，再读取官方历史计算增星。搜索不是全站扫描，分类和榜单只对当前采样集合有效。

Token 为可选项，只发往 GitHub，并保存在当前标签页的 sessionStorage；旧版 localStorage Token 会迁移后删除。也可在控制台执行 `githubPulse.setToken('')` 清除会话 Token。不要把 Token 写入仓库文件。

## 数据与统计口径

三日 Top10、周 Top10、月 Top30 只纳入对应窗口内新建的仓库，使用 [GitHub Star History API](https://docs.github.com/en/rest/activity/starring#get-repository-star-history)：`GET /repos/{owner}/{repo}/stargazers/history?per_page=6&page=1`，版本 `2026-03-10`。汇总最近 3/7/30 个**完整统计日的新增 Stars**，创建窗口与增长窗口相同，采用共同日界。旧工程无论涨星多少都不参与这些主榜。当前未结束统计日的新建工程下一统计日再纳入；日界按接口周时间戳确定，不声称精确滚动小时或 UTC 日。新增不扣除取消收藏，所需历史未知时不补零。

页面增长指标与榜单固定使用官方新增 Stars，统计截止时刻直接显示在标题附近。主榜显示窗口、候选、有效覆盖和待补数量，并非 GitHub 全站 Top。近三年总星榜按当前 UTC 年及滚动三年窗口内的创建年份分别取 Top30，按最近成功采样的累计 Stars 排序；当前年默认展开，其他年份可折叠，领域筛选后重新排名。

官方历史保存在 `src/data/star-activity.json`，浏览器也会缓存成功结果。缓存两小时后分批更新；截止时刻取采样时已结束的统计日，并限制在接口实际返回的最新周末。周日不要求存在空白的新周记录。延迟或失败时保留距今不足七天的完整历史，明示实际截止时间；排名优先最近的完整日期，同日采用多数记录的日界。七天以上旧历史不入榜，未结束日的占位零与部分计数不参与。API 返回缺周、无效数据、限额、错误或超时时保留缓存；未知数据不会补零（仅核验创建时间之前的统计日可确定为零）。页面显示错误及覆盖数量，可配置 Token 后重试。浏览器每批最多请求 40 个工程，有 Token 时最多 120 个，优先补缺并逐步展示成功结果。

`npm run sync` 优先将约三分之一请求预算用于官方历史，剩余预算采集元数据；本地后台服务与 GitHub Actions 均使用该流程，历史文件随工作流一起发布。历史队列保留新建与已有工程两条通道，每通道约三分之一名额用于最久未服务的记录；小预算批次保存轮转位置，避免热门工程长期挤占旧历史。失败工程短暂冷却并记录尝试时间，不阻塞后续候选。新响应若使仍有效的 3/7/30 日或上周历史由已知变未知，则保留原完整缓存与原采样时刻，不拼接未结束日。

仅补齐官方历史可运行 `npm run sync:history -- --limit 300 --budget 300`。浏览器中的 Token 不传给后台；命令行使用已有 `GITHUB_TOKEN` 或 `gh` 登录。额度不足时等待限额重置，不需要等待 7/30 天累积。

| 内容 | 口径 |
| --- | --- |
| 已收录工程 | 已保存快照与当前公开 API 样本的并集；404/不可公开访问项不参与榜单 |
| Stars / Forks / Open Issues | GitHub API 原始计数；未知值显示 —，页面加载和刷新不生成模拟增量 |
| 每日更新 | 最近推送时间 `pushed_at` 位于当前时间前 24 小时内；不以涨星代替代码更新 |
| 日 / 周 / 月净增 | 当前 UTC 日成功采样的 Stars，减去精确前 1 / 7 / 30 个 UTC 日期最后保存的 Stars；包含取消收藏，允许负值 |
| 净增时间精度 | 按日采样的差值，并非精确滚动 24/168/720 小时事件数；某日期基线缺失就显示“暂无基线”，不找最近日期凑数 |
| 一周 / 一月飙升榜 | 全部已收录工程按最近 7 / 30 个完整统计日官方新增 Stars 排名，各取 Top30，不限创建时间；历史日界不一致或缺失的工程计入待补，不补零 |
| 加速上升标记 🚀 | 本周官方新增 ≥ 上周 3 倍且本周 ≥ 20 颗；上周为零且本周达标的标记为“新爆发”；上周历史缺失则不标记 |
| 三日 / 周 / 月新建增星榜 | 仅对应 3/7/30 个完整统计日内新建工程，按同一窗口官方新增排序，取 Top10/Top10/Top30；先分类与搜索，再排名 |
| 近三年总星榜 | 按 API `created_at` 的 UTC 年分组，每年按当前累计 Stars 取 Top30；不是当年新增或年底历史榜 |
| 分类 | 本项目按 topics、描述、名称、语言加权推断；主分类用于筛选，详情中最多展示三个次标签；十个领域加未分类，不是 GitHub 官方分类。规则版本变化后自动重算，人工修正可通过 `categoryOverride` 保留 |
| 商机研究分 | 自定义参考分；增速项使用官方一周新增 Stars，推送、计数、许可数据缺失则不评分；未知许可证不能当作宽松许可 |
| 贡献者 | 仓库和搜索接口不含该计数，保持未知，取消按 Stars 推算 |
| 描述翻译 | 采集器每轮持久化翻译一批工程描述为中文（默认 50 条，Google 翻译优先、MyMemory 兜底，按官方一周新增 Star 降序，飙升榜最先获得中文），原文变更后自动失效重译；`--retranslate` 可将非 Google 译文升级到更优提供商；页面默认显示中文、悬停看原文。浏览器“翻译描述”按钮走同一提供商链即时补译当前目录页的最多 15 条；失败/超时保留原文 |

准确采集时刻缺失的旧记录显示快照日期，不伪造为“刚刚同步”。旧数据中无依据的创建日期、最近推送和贡献者等字段已清空；后续真实采集会补齐。单日总数无法恢复本地净增基线；默认新增榜改用官方历史直接获取，也不补造接口缺失的记录。

未保存可追溯采集时刻的旧导入记录仅保留为待核验候选，不参加当前统计与榜单；API 成功采集后才纳入。候选数量在页面上单独披露，既不把它们当作已核验数据，也不凭记录不完整就断言仓库不存在。

仓库优先按稳定的 `githubId` 去重，缺少 ID 且无身份冲突时才按全名匹配；改名时迁移本地日快照与官方历史。同名不同 ID 不继承旧身份的历史。浏览器与采集器共用合并规则：原文未变保留中文译文，人工分类覆盖保留；浏览器每次重算时也执行滚动三年过滤，长时间打开页面不会重新计入超龄工程。

同样缺少完整采集证据的 2026-09-24 旧历史已另存 `src/data/legacy-history.json`，不再作为有效涨星基线。旧版内嵌模拟涨幅不导入，避免重新引入未经验证的差值。

## 持久化采集

```bash
npm run sync
# 只采集少量已收录仓库
npm run sync -- --no-discover --limit 35 --budget 35
# 查看结果但不保存文件
npm run sync -- --dry --limit 5 --budget 10
```

采集器按优先级分批更新：上周官方新增达到 100 的活跃工程按 48 小时陈旧对待优先刷新，最近推送落在 24 小时边界附近（18–36 小时）的工程获得次优先权，避免"每日更新"因陈旧元数据误判；其余工程按最久未成功采集排序，同等旧的记录优先补齐创建时间未知项。它按响应头限额停止，后续运行会继续未覆盖项。单仓库失败保留最后成功数据，404 项暂时退出榜单并延迟重试，全部失败返回非零退出码；失败尝试不会推进成功采集时间。

默认查询 3 / 7 / 30 天、滚动三年窗口内的创建年份，以及三个星数分层（50–500、500–5000、5000+）且近一周有推送的活跃仓库通道，共 10 组候选，每组最多两页，优先继续尚未完成的查询组；官方历史优先补齐近期新建与热门工程。只收录近三年创建的工程，超龄工程每轮采集开始时连同其 Stars 历史一并移除。少于 1000 星且近 36 小时内已采样的工程在元数据与历史队列中让位于高星工程，产能紧张时约隔日轮转；周新增 ≥100 的热门工程不受让位影响。

另有星数分层打捞模式：`--harvest --harvest-min N [--harvest-max M] [--harvest-delay MS]` 把范围内 ≥N 星的工程按星数区间递归切片（每片不超过 1000 条结果）并全量翻页收录，替代常规发现；用于把高星段覆盖率补齐到接近全量。请求间默认间隔 2.2 秒以避开搜索限额；定时任务每周一 06:13 批次自动对 ≥1000 星段做一次增量打捞。发现阶段结束后，剩余预算同轮试探新候选的官方历史，确认增长的工程立即具备入榜资格，无需等待下一轮。`--discovery-pages N`、`--limit N`、`--budget N` 可调整；所有查询仅采集公开仓库。`--no-discover` 跳过发现阶段。快照和历史分别原子替换，先写历史再写快照。

描述翻译随每轮采集执行：`--translate-limit N` 控制单轮条数，`--translate-delay MS` 在请求间加入间隔以适配批量任务，`--retranslate` 仅重翻非 Google 来源的存量译文。本机定时任务「GitHub Pulse 每日同步与翻译」（Asia/Shanghai）每天执行八轮：05:13 / 06:13 / 07:13 / 08:13 四轮早间全量批（每轮元数据上限 3000、总请求预算 4600，包含约三分之一官方历史预算）；09:13 / 13:13 / 17:13 / 21:13 四轮日间热榜批（不发现新仓库，元数据上限 300、总预算 450）。每轮翻译上限 250 条；每周一 06:13 加入 ≥1000 星的分层打捞。实际覆盖取决于额度和请求耗时，不保证指定时刻完成全库更新。采集器以 `src/data/.sync.lock` 文件锁互斥：存活进程持锁期间不因运行超过 30 分钟而被接管；确认原进程退出后才回收。每次持锁有独立标识，释放时必须匹配；短期 guard 串行化取得与释放操作，避免并发竞争。

恢复或更新本机八轮任务可运行 `powershell -ExecutionPolicy Bypass -File .\scripts\install-sync-task.ps1`。默认使用当前用户的 S4U 登录方式，无需保存 Windows 密码；任务可在注销后运行，启动时读取现有用户 Token。八轮任务忽略重叠实例、单轮最长 55 分钟，开机后允许补触发；补触发按实际启动时段选择批次。日志写入 `.scratch/scheduled-sync/`。`scheduled-sync.ps1 -PlanOnly` 可检查参数，`-VerifyConnection` 只验证网络与凭据。`-InteractiveOnly` 安装选项用于仅需登录期间运行的环境。

长期采集优先使用环境变量 `GITHUB_TOKEN`，未设置时也会尝试现有 `gh auth token`；凭据不写入快照或日志。GitHub 未认证 REST 通常只有 60 次/小时，个人 Token 通常为 5000 次/小时；GitHub Actions 内置 Token 通常为每仓库 1000 次/小时，以实际响应头为准。[官方限额说明](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)

`.github/workflows/sync-data.yml` 配置每两小时分批采集（每轮最多 750 个已有仓库，总请求预算 800，另受 API 剩余额度约束）。采集数据不再提交进 Git 仓库：每轮下载上一轮滚动 artifact `github-data-latest`，将包内三个 JSON 恢复到 `src/data` 并校验；采集结束后再次验证文件完整性，以同名 artifact 发布（保留 30 天）。即使采集步骤失败，也保存校验通过的历史与状态，工作流仍报告失败；损坏或缺失文件不发布。仓库不再承担大体积 JSON 的合并与膨胀。浏览器不会把 API 结果自动写回磁盘文件；本机数据以本地采集为准。

## 文件

- `src/data/github-snapshot.json`：采样仓库、原始计数、元数据、逐仓库时间和采集覆盖说明。本地生成，不纳入 Git 跟踪。
- `src/data/star-history.json`：每个仓库每个 UTC 日期的最后成功 Stars 样本；采集器保留约 45 天。本地生成，不纳入 Git 跟踪。
- `src/data/star-activity.js` / `star-activity.json`：GitHub 官方日新增历史、聚合、缓存与限额回退。JSON 为本地生成，不纳入 Git 跟踪。
- `src/data/history.js`：日采样净增与曲线。
- `src/data/github-data.js`：分类、聚合、API 映射、榜单筛选与可选翻译。
- `src/data/repository-state.js`：稳定身份去重、字段合并和改名历史迁移，供页面与采集器共用。
- `scripts/sync-github-data.mjs`：持久化采集。
- `scripts/validate-data-artifact.mjs`：恢复与发布时校验三类 JSON，允许保留失败批次的有效进度。
- `scripts/serve.mjs`：仅提供页面需要的静态文件，隐藏目录、凭据和脚本不可通过网页读取。
- `DATA_SOURCE_AUDIT.md`：修复前的审计记录；当前行为以本 README 和实现为准。
