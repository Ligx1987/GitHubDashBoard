数据口径与使用说明

看板记录已收录公开仓库的真实采样。覆盖范围有限，无法代表全部 GitHub 工程；每个仓库的采样时间可能不同。

开始使用

运行 npm run dev，打开 http://localhost:4173。页面先读取保存的快照，再自动请求公开 GitHub 数据，之后每 30 分钟刷新。无需 Token 即可使用；限额不足时保留最近快照并显示原因。

搜索和领域筛选会先作用于全部已收录仓库，再分别计算各个 Top 榜。点击仓库行可打开 GitHub。Ctrl/⌘ + K 聚焦搜索，回车打开搜索结果中的首个已收录工程。

每项数字是什么意思

区域统计口径
已收录工程公开采样集合，不是 GitHub 全站总数。404 或不可公开访问的仓库不参与榜单。
每日更新GitHub 最近推送时间位于过去 24 小时；不把新增 Star 当作代码更新。
周 Top10、月 Top30当前 UTC 日采样的 Stars 减去前 7 / 30 个 UTC 日期的最后保存值。按日采样，不是精确到小时的滚动窗口；取消收藏会产生负净增。
暂无基线 / —缺少真实历史或对应字段，不能计算；不代表涨星为 0，也不会显示模拟值。
7 日曲线相邻 UTC 日期的真实 Stars 差，标明每日覆盖的仓库数。缺测留空，不同日期样本范围可能不同。
新建及年度榜按 GitHub 仓库创建日期筛选、按采样时总 Stars 排序。年度榜不是某个历史年度内的涨星榜。
分类基于 topics、名称、描述、语言的自定义规则，可有误差；未命中显示“未分类”。
商机研究本项目的参考分，不是官方评价或商业授权判断。必要数据不足时不评分；未知许可证单独标注。
采样新鲜度最近 24 小时成功采集的仓库数。缺少可追溯采集时刻的旧导入记录仅保留为待核验候选，暂不参加当前榜单。

让数据持续累积

浏览器刷新仅更新页面内存。本地服务运行时每两小时自动采集并保存元数据与每日 Stars 历史；关闭本地服务后采集暂停。也可手动运行 npm run sync。首次运行只能建立基线，真实周/月涨幅需要相应日期的历史记录。

采集器按最旧成功时间分批更新，自动发现近期新建仓库；遇到限额会停止，下一轮继续未覆盖项。部分失败保留可用数据，全部失败会报告失败。项目附带每两小时采集的 GitHub Actions 配置，需要推送至 GitHub 并启用工作流才会执行；静态网站还须部署最新数据文件。

Token 与翻译

可选 GitHub Token 只发往 GitHub、保存在当前标签页会话中。它提高请求额度，但不能生成缺失的历史。不要将 Token 写入工程文件或截图。控制台 githubPulse.setToken('') 可清除它。

描述默认保留 GitHub 原文。点击“翻译描述”会把当前筛选中的前 30 条（或已展开数量）描述发送至 MyMemory，结果标注“机器翻译”。失败或超时保留原文，不阻塞数据同步；翻译可能不准确。

为什么与 GitHub 页面不一样

旧快照和当前 GitHub 值存在时间差；搜索只取高星工程及近 7 / 30 / 90 天新建范围的前 100 个结果。界面会披露更新数量和采样范围，因此空榜不能推断 GitHub 没有符合条件的仓库。
