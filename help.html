GitHub Pulse 使用说明

开源工程看板 · 实时榜单 · 分类探索 · 描述自动翻译

快速开始

npm run dev
# 然后浏览器打开 http://localhost:4173

项目是纯前端静态页面，无任何依赖，也可以用任意静态服务器（如 VS Code Live Server）打开。

数据模式

看板有两种数据来源：

  • 演示快照（默认）：内置 105 个代表性开源工程，创建时间为各工程的真实创建日期（年-月级精度，日为当月合理值），因此 2022-2025 的年度榜是真实的历史分布；"立即更新"做模拟增量同步，开箱即用。由于追踪的工程中没有 90 天内新建的，本周 / 本月 / 本季度新增榜与当前年份的年度榜在演示模式下为空——这是设计行为，不是 bug。
  • GitHub 实时数据：在侧栏"GitHub Token（可选）"输入框填入 Token（或控制台执行 githubPulse.setToken('ghp_你的token')），之后点"立即更新"会改为调用 GitHub Search API 拉取真实数据（Token 只保存在本机浏览器，不会上传）。新增榜与年度榜都使用仓库真实的 created_at（客户端按 7 / 30 / 90 天窗口与自然年过滤），并额外用 created:>日期 查询专门拉取近 90 天创建的高星工程：
githubPulse.setToken('ghp_你的token')

取消实时模式：githubPulse.setToken('')。注意 Search API 有速率限制（认证 30 次/分钟），看板默认只用 4 个查询（3 个宽泛话题 + 1 个近 90 天新建工程专用），未认证时 10 次/分钟的额度同样够用。

描述实时翻译

实时模式下，拉取到的英文仓库描述会自动翻译成中文，规则如下：

  • 使用免费的 MyMemory 机器翻译接口（免密钥），中文描述和空描述自动跳过。
  • 翻译结果缓存在浏览器 localStorage，相同描述不会重复翻译、不重复消耗配额。
  • 接口故障或当日配额用尽时自动保留英文原文，不影响同步；次日配额恢复。
  • 想换 DeepL / 百度等翻译服务：替换 src/data/github-data.js 中的 translateText 函数即可（签名 (text, { signal, store }) => Promise<string>）。
机器翻译质量有限，个别技术词汇可能译得不准（例如 Container 偶尔被译成"集装箱"）。对准确度要求高时建议接入付费翻译服务。

商机评分与商机榜

看板内置一个研究价值/商业化潜力启发式评分（0-100），计算方式完全透明，可在 src/data/github-data.js 的 scoreOpportunity 中调整：

维度权重说明
周增速40周增星占 star 总数的比例，热门工程约 1-7%/周
采用度25按总 star 数取对数，规模越大生态越成熟
Fork 健康15star/fork 比在 8 附近得分最高（收藏型项目会被压低）
活跃度10最近提交距今越近得分越高
License10宽松许可（MIT/Apache/BSD）10 分；GPL/AGPL 6 分；BUSL/SSPL 等 2 分并标橙色警示

"商机榜 · Top 10" 面板按该评分排序，每行额外展示贡献者数和最近提交时间。榜单行尾的"商 XX"徽章即该工程评分（绿 ≥75 / 黄 50-74 / 红 <50）。

常见问题

  • 打不开页面？ 必须通过 http 访问（npm run dev），直接双击 index.html 会因浏览器安全策略无法加载数据模块。
  • 改了代码没变化？ 按 Ctrl+F5 强制刷新，避免浏览器缓存旧文件。
  • 榜单数字和 GitHub 不完全一致？ 演示快照中的增量是代表性数据（文件头有注释说明）；配置 Token 后即可看到真实数据。
  • 主题/翻译缓存想清空？ 控制台执行 localStorage.clear() 后刷新。
