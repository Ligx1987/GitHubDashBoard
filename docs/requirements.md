# GitHub Pulse 需求说明

GitHub Pulse 是面向开发者和开源项目研究者的公开仓库观察看板。用户可以在一个页面查看已收录项目的真实计数、最近代码推送、Stars 增长、新建项目和领域分布，并前往 GitHub 查看仓库。

本版要求所有展示指标具有明确的数据来源、统计窗口和覆盖范围。缺失数据保持未知，刷新不得制造计数或历史；排行只代表当前有效样本，不承诺 GitHub 全站覆盖。

本次调整将核心排行分为“新增工程增星看板”和“近三年总星看板”。工程收录范围限定为创建时间在滚动三年窗口内（今天减三年），超龄工程每轮采集自动移除。三个新增工程榜采用相同的创建和增星窗口，年度总星榜每年独立取 Top30；实现状态见后文。

## 产品目标与范围

### 用户与使用场景

| 用户 | 主要场景 | 需要获得的结果 |
| --- | --- | --- |
| 开发者 | 按领域、名称或语言寻找项目 | 相关仓库、描述、Stars、Forks 和 GitHub 链接 |
| 开源研究者 | 观察近期关注度和代码活动 | 有口径说明的增长排行、真实推送时间和趋势 |
| 技术选型人员 | 比较新项目、年度项目和研究信号 | 创建时间、许可证标识及数据完整时的参考评分 |
| 项目维护者 | 运行看板并持续更新样本 | 可续跑的采集、错误说明、持久化数据及运行日志 |

### 本版范围

本版提供单页看板和使用说明页，采用保存快照优先、公开 API 后续刷新、采集器持久化的工作方式。无需用户账号，也不强制配置 GitHub Token。支持本地运行及静态文件部署。

以下能力不纳入本版交付范围：GitHub 全站实时榜、私有仓库展示、平台账号与权限管理、用户收藏同步、消息订阅、历史任意日期回放，以及精确到事件时刻的滚动涨星统计。侧栏的快捷领域属于预置筛选，不是用户收藏功能。

## 页面与功能需求

页面主体为紧凑的五区块结构：顶部搜索与领域筛选、近期飙升榜（7/30 日 Tab 切换）、新建工程榜（3/7/30 日 Tab 切换）与一周趋势并排、工程目录（默认按一周新增排序）、以及收纳近三年总星榜、商机研究和每日更新的"更多视角"折叠区。导航通过页面锚点定位，使用说明位于独立页面。

下表功能均已实现，包括三组新增工程增星榜、近三年总星榜和相应候选发现。验收应同时遵守后文的数据口径与异常处理要求。

| 编号 | 功能 | 行为与验收要点 |
| --- | --- | --- |
| FR01 | 首屏与刷新 | 优先显示保存的真实快照，随后自动查询公开 API；可手动刷新。刷新中按钮禁用，避免重复请求；失败保留最近可用结果并显示原因 |
| FR02 | 搜索与领域筛选 | 不区分大小写搜索仓库全名、名称、描述、原文、语言和 topics；领域与搜索叠加。先筛选全体有效样本，再分别排序和截取榜单 |
| FR03 | 关键指标 | 展示当前筛选下的已核验工程数、近 24 小时代码更新数、周新增或净增 Stars、24 小时内成功采样数；涉及部分覆盖时披露分子与分母 |
| FR04 | 最近代码活动 | 按 `pushedAt` 判断近 24 小时更新并倒序展示；默认 5 条，可展开全部及收起；空列表说明仅针对当前采样 |
| FR05 | 新增工程增星看板 | 分别展示近 3 天新建工程增星 Top10、近 7 天新建工程增星 Top10、近 30 天新建工程增星 Top30。先按创建时间筛选，再按相同窗口内官方新增 Stars 排序；每个榜单展示实际统计起止日期与有效覆盖数 |
| FR17 | 近期飙升榜 | 对全部已收录工程按最近 7 / 30 个完整统计日官方新增 Stars 排名，各取 Top30，不限创建时间；仅日界一致的工程参与排名，其余披露为待补。本周新增达到上周 3 倍且不少于 20 颗时标记加速上升，上周为零视为新爆发，上周历史缺失不标记 |
| FR06 | 一周趋势 | 官方模式展示最近 7 个完整统计日的每日新增；本地模式展示相邻 UTC 日期的采样差。每个点展示覆盖数量，缺测留空，净减少可显示负值 |
| FR07 | 领域分布 | 使用十个自定义领域加未分类展示数量；分类采用 topics、描述、名称、语言的加权规则，主分类用于筛选，最多三个次标签辅助展示与搜索；规则版本变化后自动重算，允许 `categoryOverride` 人工覆盖 |
| FR08 | 新建工程资格筛选 | 与 FR05 合并为同一组榜单，不另设以总 Stars 排序的近期新建榜。新建以 GitHub 仓库 `created_at` 为准，首次被看板收录不算新建；同一工程可同时进入 3、7、30 天榜 |
| FR09 | 近三年总星看板 | 按创建年份分组展示当前 UTC 年及滚动三年窗口内的此前年份，每年 Top30，按最近成功采样的累计总 Stars 降序。默认全部领域，可叠加领域和搜索筛选；每个年份独立排名，当前年标注截至采样时刻 |
| FR10 | 商机研究榜 | 按自定义参考分取 Top10；增速项使用官方一周新增 Stars，计数、最近推送及已识别许可证齐全时才评分；说明其仅为研究信号 |
| FR11 | 工程目录 | 展示当前筛选下的全部已核验工程，按总 Stars 排序，初始 30 条，每次再显示 30 条；未知 Stars 的工程仍可浏览 |
| FR12 | 仓库信息与跳转 | 行内展示名称、描述、语言、许可证、Stars、Forks、创建日期与采样时间；相应榜单增加增长或评分；点击在新标签页打开 GitHub |
| FR13 | 工程中文描述 | 采集器每轮持久化翻译一批描述（默认 50 条，热门与高星优先），原文变更自动失效；页面默认显示中文并标注机器翻译，悬停查看原文。浏览器“翻译描述”按钮可即时补译当前筛选集合；服务失败保留原文与已有译文 |
| FR14 | Token 与主题 | Token 只用于 GitHub 请求并保存在当前标签页会话；主题保存在本地。提供密码输入、主题切换、Ctrl 或 Command 加 K 聚焦搜索，回车打开目录首项 |
| FR15 | 持续采集 | 采集器更新元数据、每日 Stars 和官方历史，按预算分批续跑并发现新项目；支持命令行、本地服务定时运行与 GitHub Actions |
| FR16 | 数据透明与帮助 | 显示来源、逐仓库采样时间、更新数量、历史覆盖和未核验候选数量；帮助页解释口径、限额、Token、翻译与采集方式 |

### 默认状态与交互

默认领域为全部，新增工程看板同时提供 3、7、30 天三个维度，主排行固定采用官方新增 Stars；总星看板按年份从新到旧展示滚动三年窗口内的创建年份，默认展开当前年，其他年份可折叠。主题为深色或用户上次选择的主题。分类或搜索变化后，目录展示数量重置为 30。

本地净增保留为辅助分析口径，独立标注，不替代三个新增工程主榜。顶部增长指标与一周趋势继续标明其筛选集合和新增或净增口径，不能把所有已收录工程的增长总量标成新建工程榜的总量。

浏览器在页面可见时每 30 分钟自动刷新数据，每分钟重算展示状态以反映时间变化。自动刷新与手动刷新执行相同的数据校验规则。采样时间代表真实成功请求，不得用打开页面或点击刷新时间替代。

## 数据范围与统计口径

### 有效样本与字段

已保存仓库与本轮搜索样本合并并去重。只有具有可追溯采样时间、处于公开可用状态的仓库参与当前统计和排行。未核验旧导入仅保留为候选；404 或不可公开访问项退出榜单，后续采集可重试。

浏览器每批查询 3、7、30 天新建候选及一个年度，每组取按总 Stars 排序的前 100 项，四个年度在成功批次间轮换。近期发现多查询一天以覆盖日界差异，榜单仍按实际窗口严格筛选。持久化采集覆盖三个近期窗口和滚动三年窗口内的年度，并记录查询分页、截断与完成时间。按总 Stars 搜索取样不能直接当作增星排名，必须再获取历史并排序。页面搜索只作用于已收录集合。

### 新增工程与年度榜规则

| 看板 | 入榜工程 | 排序指标 | 上限 |
| --- | --- | --- | ---: |
| 一周飙升榜 | 全部已收录工程，不限创建时间 | 最近 7 个完整统计日官方新增 Stars | 30 |
| 一月飙升榜 | 全部已收录工程，不限创建时间 | 最近 30 个完整统计日官方新增 Stars | 30 |
| 近 3 天新建工程增星榜 | 创建于最近 3 个完整统计日窗口内的工程 | 同一窗口内官方新增 Stars | 10 |
| 每周新建工程增星榜 | 创建于最近 7 个完整统计日窗口内的工程 | 同一窗口内官方新增 Stars | 10 |
| 每月新建工程增星榜 | 创建于最近 30 个完整统计日窗口内的工程 | 同一窗口内官方新增 Stars | 30 |
| 近三年总星榜 | 按滚动三年窗口内的 UTC 创建年份分别分组 | 最近成功采样的累计总 Stars | 每年 30 |

“每周”和“每月”采用滚动近 7 天和近 30 天，不按自然周或自然月重置。“前三天”采用滚动近 3 天。为与日级历史对齐，设 B 为统一的最近完整统计日结束时刻，窗口为 `[B − N 天, B)`；创建资格和增星汇总使用同一窗口，左边界包含、右边界不包含。当前尚未结束统计日内新建的工程留待下一完整日纳入，页面必须提示此规则。

同一张榜只比较窗口结束时刻一致的历史，不能混排不同日界的统计。工程若满足多个窗口，可在多个榜单重复出现；各榜名次独立。创建日期未知、官方历史缺失或过期的工程不参与相应榜单，显示待补数量；真实零新增仍为有效值。榜单不足 Top N 时只显示实际工程，不补造条目。

年度分组按 `created_at` 的 UTC 年确定，且创建时间必须落在滚动三年窗口（今天减三年）内。以 2026 年 10 月为例展示 2026、2025、2024、2023 四组（2023 年仅含窗口内月份），各组至多 30 项；窗口随日期逐天滚动，超龄工程在下一轮采集时自动移出注册表及其 Stars 历史。年度榜按当前累计 Stars 排名，不要求三年涨星历史，也不表示该年新增 Stars 或该年年底总 Stars。默认每个年份全领域 Top30，选择领域后重新从该年份匹配工程中取 Top30，不是每个领域默认各取 30 项。

| 指标 | 本版定义 |
| --- | --- |
| Stars 和 Forks | GitHub 返回的原始计数，代表该仓库最近成功采样时的值 |
| Open Issues | 保存 GitHub 原始 `open_issues_count`，不解释为单独排除 Pull Request 的 Issue 数；当前仓库行未展示此字段 |
| 贡献者 | 当前仓库与搜索接口未提供该计数，保持未知，不根据 Stars 推算 |
| 代码更新 | 最近推送时间在当前时刻前 24 小时内；未来时间不计入，`updated_at` 不替代 `pushed_at` |
| 创建时间 | 使用 GitHub `created_at`；不能以产品发布日期或重写版本日期代替 |
| 采样新鲜度 | 当前筛选下，24 小时内成功采样的仓库数除以有效仓库数 |
| 领域分类 | 根据 topics、描述、名称和语言进行加权推断；语言只是弱证据，主分类用于筛选，次标签辅助理解；可能存在误差 |
| 许可证分类 | 实现按 SPDX 标识进行启发式分类；未知或未识别标识单列，不据此推断商业使用授权 |

### 官方新增 Stars

新增工程主榜使用项目所配置的 GitHub Star History 接口返回的周记录与日计数。三日、周、月榜分别汇总最近 3、7、30 个完整统计日，并限定在对应窗口新建的工程；当前未结束的统计日不计入。日界以接口周时间戳为锚点，不承诺 UTC 自然日或精确滚动小时。三日、周、月汇总及新建限定由同一数据模块计算。

新增表示新增收藏数量，不扣除取消收藏。所需统计日不完整则该周期指标未知；缺失早期历史可以只影响月榜，不影响具备完整数据的周榜。只有已核验创建时间之前完整结束的统计日可以确定为零，其他缺失日不能补零。

缓存刷新失败时保留原始成功记录，但缓存若已不能覆盖当前所需完整统计日，则不能继续作为当前有效排行。真实零增长仍可参与排行。

### 本地净增 Stars

本地模式比较当前 UTC 日期成功采样的 Stars 与精确前 1、7、30 个 UTC 日期最后保存的 Stars。当前采样必须属于当前 UTC 日；相应基线缺失或当前端点过期时显示“暂无基线”。

例如当前值为 110，精确 7 天前为 120，周净增为 −10；若仅有 6 天前数据，则不能计算周净增。重复同日采样更新当日值，但不改变此前日期基线。这是每日采样之间的净变化，包含取消收藏，不是精确滚动 168 小时的事件量。

### 排序与聚合

所有榜单先过滤公开可用性、领域、关键词、日期条件和所需指标的有效性，再按主指标降序排序。主指标相同时按总 Stars 降序，再按仓库全名字典序保持稳定结果。零值和负净增都是有效数值，不能按大于零统一过滤。

顶部增长总量只汇总已知值并显示覆盖数量；完全无有效值时显示未知。官方趋势只合并统计窗口结束时间一致且一周历史完整的工程。本地趋势逐日只汇总同时具备相邻两日采样的仓库，日与日之间覆盖数量可能不同。

## 异常与非功能要求

| 编号 | 要求 | 验收标准 |
| --- | --- | --- |
| NFR01 | 数据真实性 | 未知计数显示破折号，基线不足单独提示；页面加载、筛选与刷新不生成模拟 Stars、时间或贡献者 |
| NFR02 | 可用性与失败恢复 | API 错误、格式无效、超时和限额不覆盖有效缓存；页面保留可用数据并说明未完成的范围；无结果不能解释为全站无项目 |
| NFR03 | 凭据与外部数据安全 | Token 不进入仓库 JSON、日志或翻译请求；外部描述按转义文本展示；本地服务只开放页面必要文件 |
| NFR04 | 请求与资源约束 | 浏览器和采集器均设置批量、时间及请求预算；响应头触发限额停止与延后重试，不能无限循环请求 |
| NFR05 | 可操作性 | 按钮和输入项有可理解标签，提供加载、空白、缺测及错误状态；浅深主题、键盘搜索和窄屏布局可用 |
| NFR06 | 可运行与维护 | Node.js 20 或更新版本，无额外运行依赖；可执行既有自动化测试；采集结果分文件原子替换，记录逐仓库成功与尝试时间 |

本版尚未设定页面加载耗时、全量更新完成时限、最大仓库规模或服务可用率指标。两小时采集是触发频率，不保证两小时内覆盖全部仓库；实际完成速度取决于额度、批量及数据完整性。

## 验收场景

| 场景 | 预期结果 | 对应功能 | 已有自动化覆盖 |
| --- | --- | --- | --- |
| 离线打开或刷新 | 有缓存时保留真实快照；失败有提示，Stars 不发生模拟变化 | FR01、FR16 | 数据加载与 UI 失败回退测试 |
| 分类内项目未进入全局 Top | 分类榜仍能从完整匹配集合中选出它 | FR02、FR05 | 数据筛选与 UI 分类排序测试 |
| 辅助净增分析 | 本地净增与官方新增独立标注，辅助切换不改变新增工程主榜资格与口径 | FR05、FR06 | UI 辅助分析与主榜独立测试 |
| 旧工程增长高于新工程 | 旧工程不得进入任一新增工程榜，即使本周期增星更高 | FR05、FR08 | 新榜资格及 UI 测试 |
| 旧工程近期爆发 | 进入飙升榜 Top30，但不进入任一新建工程榜；加速上升有标记 | FR17、FR08 | 飙升榜资格与加速度测试 |
| 三个窗口与条数 | 3 天 Top10、7 天 Top10、30 天 Top30；可重复入榜，每榜独立排名 | FR05、FR08 | 三日汇总与三榜条数测试 |
| 创建时间恰在边界 | 窗口起点创建可入榜，终点创建不入榜；首次收录旧工程不算新建 | FR08 | 创建窗口边界测试 |
| 近三年总星榜 | 仅滚动三年窗口内的创建年份，每年至多 30 条；按当前累计 Stars 排序，跨年自动滚动 | FR09 | 年度分组、Top30 及跨年测试 |
| 年度领域筛选 | 从每年完整匹配集合重新取 Top30，不能先取年度总榜再筛选 | FR02、FR09 | 年度领域与搜索筛选测试 |
| 缺失月历史但有完整周历史 | 周榜可用、月榜未知；缺周不补零 | FR05 | 官方历史测试 |
| 本地基线缺失或出现净减少 | 缺失时未知，负值保留；同日采样不破坏昨日基线 | FR05、FR06 | 净增与采集器测试 |
| 旧候选或仓库不再公开 | 候选与不可用项不参与统计；成功核验后再纳入 | FR03、FR11、FR15 | 候选核验与公开性测试 |
