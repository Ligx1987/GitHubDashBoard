# GitHub Pulse 文档索引

GitHub Pulse 用于观察已收录公开 GitHub 仓库的代码活动、Stars 变化和新建项目。这里集中维护产品需求与技术设计，供功能评审、开发和验收使用。

| 文档 | 用途 |
| --- | --- |
| [需求说明](requirements.md) | 产品定位、功能范围、统计口径、交互要求和验收标准 |
| [技术设计](design.md) | 模块分工、数据模型、计算规则、采集流程、安全与运行设计 |
| [项目运行说明](../README.md) | 启动、采集和测试命令 |
| [历史数据源审计](../DATA_SOURCE_AUDIT.md) | 保留修复前的问题与证据，用于追溯，不作为当前功能清单 |

## 文档基线

整理日期为 2026 年 10 月 14 日，实现基线对应 `package.json` 中的 1.1.0 版本及当前工作区代码，包括尚未提交的功能改动。本次需求修订增加近 3 天新建工程增星 Top10、每周新建工程增星 Top10、每月新建工程增星 Top30，以及近三年（滚动窗口）按创建年份各年总星 Top30；工程收录范围限定为近三年创建，超龄工程每轮采集自动移除。上述看板、筛选与候选采集已实现，需求说明和技术设计记录当前行为。

需求中的功能编号用于关联技术模块和验收场景。修改功能时，应同时更新需求、设计及相关验收说明；涉及新增或净增、日期边界、数据来源、样本范围时，还需同步根目录 README 和页面使用说明。

## 阅读顺序

产品评审先阅读需求说明中的产品范围、功能需求和数据口径。开发人员在此基础上阅读技术设计的数据流与模块接口。部署与运维人员重点阅读技术设计中的采集参数、运行方式和失败处理。

85 项自动化测试在整理当日通过，覆盖数据计算、官方历史解析、采集器及页面渲染逻辑。实际浏览器布局、线上 GitHub 接口权限和远端工作流运行状态仍需按部署环境验收。
